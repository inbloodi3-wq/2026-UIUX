# Project Definition & UX Strategy — AUTORUN_02 (에어코리아)

근거는 `current-site-audit.md`에 있다. 표기: [F] 사실 · [D] 도출 · [H] 가설 · [P] 디자인 제안 · [U] 미확인.

## Project Definition
- **Target service**: 에어코리아(한국환경공단 대기환경정보) — https://www.airkorea.or.kr/web/
- **Goal**: 사용자가 우리 동네 대기질을 보고 **"지금·오늘·내일 밖에서 활동해도 되는지"를 한 번에 판단**하도록 돕는다.
- **Audience [H]** — 인터뷰·행동 데이터 없이 공개 구조와 서비스 성격으로 세운 가설
  1. 출근·운동·외출 전 확인하는 일반 성인
     - 근거: 홈의 "우리동네 대기정보"와 행동 메시지 "일상적인 실외활동 가능" [F]
  2. 아이·노약자 보호자
     - 근거: 퀵메뉴 "국민 행동요령"이 있음 [F]. 민감군별 요령이 핵심 정보라는 것은 가설 [H]
  - 검증 방법(후속): 사용자 인터뷰 또는 설문. 이번 실행에서는 수행하지 않음
- **Primary user tasks**
  1. 내 지역의 현재 대기질 확인
  2. 오늘·내일·모레 예보 확인·비교
  3. 행동 판단(외출·운동·환기 등)
- **Core flow**: 우리 동네 지금 → 오늘·내일 흐름 → 할 일 판단
- **Scope**
  - 포함: 대기질 홈(우리 동네 요약), 예보 상세 × Desktop 1440 / Mobile 390 = 4화면
  - 제외: 통계·배움터·알림 신청(개인정보 입력)·챗봇·로그인·관리자 기능, 지도 기능 재설계(참조 수준)

## Problem Definition (3)

### P1. 판단에 필요한 정보가 서로 다른 시각·패널에 흩어져 있다
- **OBSERVED EVIDENCE [F]**
  - 한 홈 화면에 기준 시각이 4개 있다: 측정 20시, 지도 20시, 경보 21시, 예보 17시.
  - 행동 메시지는 한 항목(오존)에 대해서만 나온다.
  - 지도의 기본 항목은 오존이다.
  - 예보 표에는 대상 지역 표기가 없다.
- **EXPECTED USER DIFFICULTY [H, 검증 전]**
  - "지금 기준"과 "예보 기준"을 구분하지 못하거나, 어느 항목·어느 지역 기준의 판단인지 헷갈릴 수 있다.
  - 최종 판단을 사용자가 여러 패널을 조합해 직접 해야 할 수 있다.
- **DESIGN RESPONSE [P]**
  - 3개 항목을 종합한 **"오늘의 공기" 판단 카드 1개**를 둔다.
    - 가장 나쁜 항목 기준으로 판단하고, 그 기준을 명시한다.
  - 판단 카드 바로 아래에 기준 시각·측정소·지역을 한 줄로 고정한다.
  - 측정(지금)과 예보(오늘·내일)는 시각 레이블을 분리한다.

### P2. 같은 말이 다른 지표를 뜻하고, 전문 용어가 앞에 나온다
- **OBSERVED EVIDENCE [F]**
  - 홈에서 "미세먼지" = PM-10이다.
  - 예보 표에서는 "미세먼지" 행이 PM-10·PM-2.5 행과 별도로 있고, 서울 오늘 값이 "보통"(PM-10 행은 "좋음")으로 다르다.
  - 홈 지도에 측정망 구분 5종(도시대기·국가배경·도로변대기·교외대기·항만)이 노출된다.
  - 예측모델 이미지 표의 캡션이 "측정자료 수치의 표"다.
- **EXPECTED USER DIFFICULTY [H]**
  - 같은 "미세먼지"가 페이지마다 다른 등급으로 보여 신뢰가 떨어지거나 오해할 수 있다.
  - 일반 사용자에게 측정망 구분은 판단과 무관한 선택지일 수 있다.
- **DESIGN RESPONSE [P]**
  - 용어를 한 가지 체계로 고정한다: "미세먼지 PM10 · 초미세먼지 PM2.5 · 오존 O₃". 종합 등급은 "통합 판단"으로 이름을 분리한다.
  - 측정망·모델 이미지는 "자세히(전문 정보)" 층으로 내린다.
  - 예보 표는 **내 지역 행 우선 + 전국은 펼쳐 보기**로 바꾼다.

### P3. 데스크톱 페이지를 390px로 볼 때 핵심 패널이 화면 밖에 있다
(Case Study WHY Audit 정정: 이전 제목 "모바일에서 핵심 정보까지 가는 길이 막혀 있다"는 과장이다. 에어코리아에는 별도 모바일 웹이 있고, 그 본문은 확인하지 못했다.)
- **OBSERVED EVIDENCE [F]**
  - 데스크톱 페이지는 390px에서 재배치되지 않는다. banner 폭 1402px, "오늘의 대기질" 패널 x≈1076.
  - 모바일 웹은 첫 접속 시 언어 선택 게이트를 먼저 보여준다. `/main` 직접 접근도 같은 게이트로 돌아간다.
- **EXPECTED USER DIFFICULTY [H]**
  - 모바일 사용자가 첫 화면에서 대기질을 보기까지 추가 단계가 필요하다.
  - 데스크톱 URL을 공유받아 모바일로 열면 핵심 패널이 화면 밖에 있다.
- **DESIGN RESPONSE [P]**
  - 모바일 첫 화면(390×844)에 판단 카드·3개 항목·기준 시각을 모두 담는다.
  - 언어는 헤더의 전환 버튼으로 옮긴다. 브라우저 언어 기본값을 사용한다는 전제로, 게이트는 두지 않는다 [P].
  - 반응형 단일 레이아웃으로 설계한다(Reflow).
- **[U]** 실제 모바일 UA의 자동 이동 여부, 언어 선택 이후 화면은 미확인이다. Case Study에는 이 한계를 명시한다.

## 개선 효과에 대한 입장
사용자 테스트 없이 개선 효과를 확정하지 않는다. 산출물에서는 "예상 효과(가설)"로만 서술하고, 첫 화면에 보이는 요소 수·단계 수 같은 **계산 가능한 차이**만 [D]로 제시한다.

## 제작 단계 개정 (2026-09-30)
- P1의 "통합 판단 카드"는 **"지금 가장 높은 등급" 카드**로 구현했다. 공식 통합지수와 구분하고, 행동 문구는 에어코리아 원문만 쓴다(`why-decision-log.md` W10, W14).
- P2의 용어 체계는 "미세먼지 PM10 · 초미세먼지 PM2.5 · 오존 O3"로 구현했다. 원 예보 표의 "미세먼지" 종합 행은 정의 미확인으로 싣지 않았다.
