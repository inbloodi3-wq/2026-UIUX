# UI Production Plan — AUTORUN_02 (에어코리아)

- 근거: `../research/ux-strategy.md`(P1–P3), `../design-system/visual-direction.md`(Particle Count)
- 뷰포트: Desktop 1440 / Mobile 390(첫 화면 844)
- Screen ID 규칙: 기본값 `{domain}-{screen}` + variant `.desktop` / `.mobile`
- 샘플 데이터: 2026-09-30 20시 서울 중구 측정소 공개값 [F]
  - 오존 0.0544ppm 보통 · PM2.5 13㎍/㎥ 좋음 · PM10 19㎍/㎥ 좋음
  - 예보 17시 발표분
  - 화면에 출처·기준 시각을 표기한다.

## 1. `c-air-now` — 우리 동네 지금 (Master Screen: `c-air-now.desktop`)
- **화면 목적**: 한 화면에서 "지금 밖에서 활동해도 되는가"를 판단한다(P1).
- **사용자 과제**: 내 지역 확인 → 종합 판단 → 3항목 수치 확인 → 오늘·내일 흐름 보기
- **정보 구조(우선순위 순)**
  1. 위치 바: 지역·측정소("서울 중구 · 중구 측정소"), 위치 변경, 즐겨찾기
  2. **판단 카드**
     - 통합 판단 등급 + 행동 한 줄 + "기준: 오존(가장 높은 등급)"
     - 기준 시각 "측정 2026.09.30 20시"
  3. 3항목 수치 행: 미세먼지 PM10 · 초미세먼지 PM2.5 · 오존 O₃ — 값, 단위, 등급 배지
  4. Particle Field(Hero Artwork) + 시각화 기준 caption
  5. 오늘·내일·모레 예보 small multiples
     - "예보 17시 발표" 레이블로 측정 시각과 분리
  6. 경보·특보 한 줄. 없으면 "발령 없음"과 기준 시각
  7. 행동요령 진입(국민 행동요령) · 전문 정보(지도·측정망) 진입
- **핵심 컴포넌트**: `loc-bar`, `verdict-card`, `pollutant-row`, `grade-badge`, `particle-field`, `forecast-mini`, `alert-line`, `timestamp`
- **디자인 방향 적용**
  - 판단 카드 배경 = 가장 나쁜 항목의 등급 틴트
  - 필드 입자 = 3항목을 한 필드에 겹쳐 그림(크기·형태로 구분)
  - 대형 수치 Display 96
- **Responsive**
  - Desktop: 좌 5 / 우 7 비대칭, 필드 bleed
  - Mobile: 판단 카드와 3항목이 첫 화면(y ≤ 844) 안에 온다. 필드는 390×200 띠로 줄여 그 아래에 둔다(Priority 유지, Artwork 축소).

## 2. `c-air-forecast` — 오늘·내일·모레 예보
- **화면 목적**: 내 지역 3일 예보를 비교하고 이유를 확인한다(P1·P2).
- **사용자 과제**: 날짜별 등급 비교 → 가장 나쁜 날·항목 파악 → 원인 요약 확인 → 필요하면 전국 비교
- **정보 구조**
  1. 제목 "서울 · 3일 예보" + "국립환경과학원 대기질통합예보센터 · 2026.09.30 17시 발표"
  2. **예보 매트릭스**
     - 행 = PM10 / PM2.5 / O₃, 열 = 오늘·내일·모레
     - 각 셀에 등급 배지와 mini particle field
  3. 통합 판단 줄: 날짜별 가장 나쁜 등급
  4. 원인 분석 요약(날짜별 1–2문장, 공식 문구 인용 + 출처)
  5. 용어 안내 inline
     - "미세먼지 = PM10, 초미세먼지 = PM2.5"
     - "오존 예보 기간 4.1–10.31, 당일 등급 05·11시 발표"
  6. "전국 보기"(접힘): 19권역 표, 내 지역 행 강조
  7. "전문 정보"(접힘): 예측모델 이미지 자리(외부 이미지 사용 안 함 → placeholder + 링크 주석)
- **핵심 컴포넌트**: `forecast-matrix`, `grade-badge`, `particle-field/mini`, `verdict-strip`, `cause-note`, `term-hint`, `disclosure`, `region-table`
- **디자인 방향 적용**: 셀의 mini field로 날짜별 변화를 형태로 비교한다(small multiples).
- **Responsive**
  - Desktop: 3열 매트릭스
  - Mobile: 날짜별 세로 스택(오늘 → 내일 → 모레). 각 날짜 카드 안에 3항목 한 줄씩. 19권역 표는 가로 스크롤 대신 **내 지역 + 권역 선택 목록**으로 줄인다(Priority Reduction).

## 3. 첫 화면 비교 지표 (계산 가능한 것만)
| 지표 | 현행 [F/D] | 목표 [P] |
|---|---|---|
| 모바일 첫 화면에서 대기질 수치까지의 단계 | 모바일 웹: 언어 게이트 1단계 후 본문(본문 구성 미확인 [U]) / 데스크톱 URL: 패널이 가로 범위 밖 | 0단계(첫 화면에 판단 + 3항목) |
| 홈 한 화면의 기준 시각 개수 | 4개(20·20·21·17시) | 2개(측정·예보), 레이블로 구분 |
| "미세먼지" 용어의 의미 | 페이지마다 다름 | 1개로 고정 |

개선 효과(이해도·만족도)는 사용자 테스트 전까지 주장하지 않는다.

## 4. 제외·주의
- 알림 신청(개인정보 입력), 로그인, 챗봇은 설계하지 않는다.
- 지도는 재설계하지 않는다. "전문 정보"로 가는 진입점만 둔다.
- 에어코리아 로고·캐릭터·지도 이미지는 쓰지 않는다. 텍스트 워드마크 "에어코리아(리디자인 콘셉트)"를 쓰고, 비공식 고지를 푸터에 둔다.

**계획 대비 변경**(근거: `../research/why-decision-log.md` W9–W14, `../design-system/visual-direction.md` 5-1)
- 판단 카드 이름: "통합 판단" → **"지금 가장 높은 등급"**. 공식 통합지수가 아님을 예보 화면에 명시했다.
- 행동 한 줄: 새 문장을 만들지 않았다.
  - 지금 화면은 원 홈 문구를 원문 인용한다.
  - 행동요령(민감군/일반인)은 예보 화면에서 해당 예보 등급에만 연결한다.
- 지금 화면의 Particle Field: 3항목 겹침 → **항목별 3칸**
- 예보 화면의 mini field → **항목 아이콘**(예보에는 수치가 없음)
- 예보 오늘 오존: 17시 발표에 없어 **"17시 발표 없음"** 상태로 표시했다(값 생성 없음).
- 추가: 공식 **예보 등급 구간 표**(원문)와 용어 안내("미세먼지" 종합 행 미게재 사유)
- 모바일 19권역 표: "권역 선택" 접힘 진입점으로 축소(Priority Reduction)
- 경보 영역은 지금 화면에만 둔다. 예보 화면에는 경보를 두지 않는다(21시 기준 발령 없음).
